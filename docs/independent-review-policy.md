# Independent review and shared recovery

The human selected independent agent primary review with OCR optional after retained TrucX evidence showed provider/budget/collection failures as well as genuine findings. #401's latest completed OCR execution selected 17 paths, completed none, failed fourteen for budget and three for provider errors, and recorded 1,397,498 tokens with a 1M setting. #423's screenshot represented historical failures; its fresh attempt had no terminal report at inspection. These are distinct from its six independently reproduced compiler/source defects. OCR still produced useful findings on #448/#109; old failures are retained, never relabelled passed.

The primary controller review now uses a fresh native spawn under the exact coordinator, with no implementation-history fork. It is a separate reviewer from the implementer/original team. Child-scoped native-mode and monotonic tool guards permit only read-only inspection plus native structured result capture. Exact base/head/tree, literal Git paths, raw diff/context snapshots and SHA256 fingerprints are bound to the request. Actual successful native read receipts must cover every snapshot line and match its bytes. Structured coverage must inspect every changed path exactly once, with substantive scope/explanation and no skipped/failed/waived coverage. Native terminal outcome, session/parent identity and input/output/cache/retry token buckets are retained in the report. Per-response output limits inherit the configured model; no arbitrary lower review ceiling is introduced. Each independent review has its own explicit 1M aggregate budget, not a shared pool.

Configured verification remains mandatory. Clean HEAD/current target are checked before and after review. Policy identity includes backend, optional OCR selection and budget; changes invalidate stale cache/merge admission. Native child disposal is awaited, and failed quiescence rejects completion while retaining read-only protection. OCR is disabled by default for agent mode and can be explicitly enabled as a supplemental check. Its incomplete transport/coverage is recorded without masquerading as a passing OCR verdict; actual complete high/medium/critical findings remain blockers. Legacy saved implicit OCR runs retain that policy until explicitly changed, including unrelated configuration updates.

More than four parked tickets or three consecutive scheduler failures holds new intake and creates/reuses one dedicated non-ticket recovery session/workspace per run. It uses the original automatically approved team and is excluded from ticket claim/admission counts. Shared CI/review/plugin/environment causes are authorized investigation/repair scope even without a tracker item; existing owners such as #453 are reused. Repository patches pass the normal original-team, exact-head independent review, CI and provider PR gates with no fake closing issue. Environment/plugin/existing-owner recovery can settle from genuine fresh completed reports, verified owned idleness and a clean/unmodified recovery repository; source changes cannot use this path to bypass PR checks.

Only explicitly affected existing assignments receive durable recovery intents. Unknown/busy ownership, unmet dependency proof and failures keep those intents pending; newer explicit/worker-reported holds revoke old intents. Successful shared merges require affected branches to incorporate the target commit and repeat exact-head validation. The same recovery workspace/session can continue a new episode on a clean new branch, preserving its report/history. Settled lower-count cases stay quiet. Pause/Stop/Drain/bounded completion preserve ownership until both recovery work and independent grading quiesce. A two-GiB prepare guard avoids creating more work under low disk pressure. The human's existing-only intake mode is never automatically reopened.

The 30-minute maintenance heartbeat follows this policy and prioritizes actual recoverable holds and plugin defects. Browser/device/legal/provider prerequisites remain real external holds, not review or CI waivers. A regression suite and authenticated native evidence are required before claiming deployment; successful installation does not imply every ticket is delivered.
