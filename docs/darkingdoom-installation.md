## Windows background launch

From this checkout, run `pwsh -NoProfile -File scripts/start-dsh-web.ps1`. It starts the pinned local DSH CLI as a separate hidden Node process, explicitly selecting the `web` profile and loopback port 3080. The host survives the launching terminal closing. A second invocation reuses the matching listener; it refuses to replace another process occupying the port. The private SDK path is applied only to the child process. BrowserSkill startup is not required.

Startup output and errors are retained separately under `%DSH_HOME%/logs` (normally `%USERPROFILE%/.dsh/logs`). The stdout log contains the private local authentication URL; use that URL if a restarted host asks you to sign in again. Do not publish or commit these logs. This launcher does not add login tasks, reboot startup or a crash-restart policy.

The existing user shortcut `.dsh/start-darkingdoom-web.cmd` can invoke this script. A stopped server is distinct from a paused/parked delivery task: current run/session/worktree state is restored when the host starts, and parked tasks are not silently resumed. Successful authenticated status requests prove host/plugin availability, not completion of task acceptance or external review gates.

To edit a stopped run, open Configuration and Save configuration, then Resume from Monitor when ready. Ticket IDs exposes the saved trial allowlist; clear it and set Ticket limit 0 for future continuous intake if intended. Existing task contracts/history are preserved, parked work remains parked, and the flow does not start from a save. Tracker/repository identity remains bound to the run.
