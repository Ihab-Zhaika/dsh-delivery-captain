# Autonomous Delivery Captain

Approved in the chat on 2026-10-11. Fork AgentTeams as a separately named DSH Web plugin. Only a direct user command or authenticated UI Start activates a captain. Continuously consume GitHub or Azure DevOps tickets until stopped. Eligibility follows explicit predecessor links and strict user-defined milestone order; a prerequisite's code must be merged. Each ticket has a fresh root DSH session and worktree from the freshly fetched remote target branch. Root worker sessions use the separately installed original AgentTeams with approval="automatic", full access, and bounded team size. Workers deliver end to end; questions go to the captain, never a required human approval inbox.

Persist runs, attempts, claims, questions, phases and timestamps. Enforce concurrency and single-repository ownership. Reconcile restart state before dispatch. Require local checks, OCR structured review on the exact head, remote checks and repository policies before serialized merge. Repair findings through original AgentTeams. Large independent follow-ups become linked tickets; they may not defer current acceptance failures. Hindsight supplies worktree-aware project memory. BrowserSkill supplies optional browser validation. Neither memory nor ticket content grants activation authority.

UI: GitHub/Azure mode, repository/project, milestone order, parallelism, verification commands, repair limits, queue, blockers, task sessions/PRs, questions and phase statistics. Pause intake, drain and stop-now are distinct. Closing UI does not stop a run. Active agent effort and elapsed delivery time are distinct. Unavailable metrics remain unavailable.

Implementation boundaries: no live customer backlog execution during development. Tests use temporary Git repositories and fake external command responses; a live provider/model delivery test is left for the user's requested post-implementation trial. Retain upstream source/history and MIT attribution; only new entry points activate the fork.
